The frame is sandboxed without allow-same-origin, so it runs at an opaque origin. The SDK learns which slot it is, and which entry to import, from the connect handshake the host sends. See docs/extensions/asset-serving.md. script-src names both 'self' and the site URL on purpose. 'self' covers a site reached on a second hostname, where the site URL would name the wrong origin. The site URL covers a browser that does not match 'self' at an opaque origin. blob: is what runs an installed extension. No route can serve one user's copy of it, because this frame sends no session, so the host reads the file under its own and posts the code in the handshake. The SDK turns that string into a module through a Blob URL. Nothing else here loosens: an extension still reaches no origin but the site's own. extension_dev_origins adds localhost on any port, but only where the site runs in developer mode. An extension loaded from a dev server imports its entry from there, and its hot reload opens a websocket back to it. Both are refused by the policy above, and neither can name its port in advance. An import map is an inline script, so script-src blocks it without a hash or a nonce. The map never changes, so it takes a hash. Both the hash and the script body come from import_map below, which is what stops the two drifting apart.
