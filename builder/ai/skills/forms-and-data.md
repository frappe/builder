# Forms and data

- Forms that collect input (contact, booking, reservation, signup, waitlist, RSVP, "get in touch") must actually save; a form that goes nowhere is a broken feature. Call connect_form(doctype_name, fields, form_selector): it creates a private submissions DocType, a guest-safe Web Form, and the submit script, all confirm-gated. List the `fields` in the same order the inputs appear in the form (the tool maps inputs to fields positionally, so order matters); one field per input/select. `form_selector` is a best-effort hint (a class on the form container if it has one, else the section); the tool auto-finds the form if the selector misses, so you do not need to pre-set name attributes or a class. After approval, your summary must give the user the Desk link it returns (/app/<doctype>). Do not hand-roll form submission with a raw script, connect_form is the only correct path (guest visitors can't insert directly).
- A question about a form's submissions ("where are the booking submissions?", "how do I see form entries?", "where does this form save?") is a read, not a build: answer it. The submissions live in a DocType; find it (query_records for a Builder submission doctype, or note the page's 'Save <X> submissions' script) and reply with its Desk link [/app/<slug>](/app/<slug>) and roughly how many entries. Do not call connect_form for a question, and never create a second doctype for a form that's already connected.
- Data-driven content (a list/grid of events, products, team members, posts, testimonials pulled from real records) → first list_doctypes / get_doctype_schema to find or understand the data, then write_page_data_script to populate `data` (e.g. `data.events = frappe.db.get_all('Event', fields=[...])`) and bind a repeater to it. get_all reads regardless of who is viewing, so ask only for the fields and rows the page should publish, and never put private records (users, form submissions) on a public page. If no suitable DocType exists, propose create_doctype, then seed_sample_data so the page isn't empty (both ask the user to confirm first). A list you write yourself (a menu, opening hours, a team) is content, not data: it goes in the brief and lands as blocks the user can edit on the canvas, never in a data script.
- Rows read from an outside API or feed (an event's speakers, a product feed) are data too. Write them into the data script as a list holding only the fields the page shows (data.speakers = [{"name": ..., "photo": ...}, ...]) and bind one repeater to it. The page then renders whether or not the other site is up. Fetch live with frappe.make_get_request(url) only when the user wants the page to follow the source, inside try/except so an outage renders an empty list, not a broken page.
